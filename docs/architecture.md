# Magpie 통합 설계 및 구현 계획

## 목표와 경계

생성형·판단형·임베딩 작업을 공급자와 독립적으로 관리하는 AI 게이트웨이. OpenAI, Anthropic, Gemini, EXAONE, TypeSafe Jev와 사용자 정의 OpenAI 호환 공급자를 검증 대상으로 삼는다. A2A, MCP 서버와 도구 실행은 범위에서 제외한다. 생성형 function calling의 요청과 결과 전달은 별도다.

생성 API에서 함수 정의와 함수 호출 이력만 허용한다. 공급자가 직접 실행할 수 있는 MCP, 웹 검색 등 다른 유형의 도구 정의와 선택은 공급자에 전달하기 전에 거부한다. 함수의 실행은 클라이언트의 책임이다. 함수 호출 이력의 내부 객체는 이름과 문자열 인자만 허용하며, 추가 공급자 도구 필드는 거부한다.

범위는 공급자 연결, 생성·판단·임베딩 모델 관리 및 API, 공급자 키·클라이언트 인증, 사용량과 감사 이력에 집중한다. 사용자 결정에 따라 SSO, 예산·정산, 모델 라우팅은 제거한다. 기존 DB 데이터는 보존하며 관련 API와 실행 경로를 제거했다. 신규 요청은 허용된 모델 별칭을 직접 사용한다. 기존 예산 키는 무제한 사용을 막기 위해 차단하고 새 키로 교체한다. LiteLLM 패키지는 어댑터로 포함하되 자체 프록시의 관리 화면·관리 API·문서 파일, A2A 프로토콜·에이전트 엔드포인트와 MCP 서버 구현을 백엔드 이미지에서 제외한다. LiteLLM의 일반 호출 경로가 참조하는 MCP 설정 모듈 `stdio_gate.py`와 그 밖의 패키지 내부 의존성은 유지한다. MCP나 A2A API는 제공하지 않는다.

## 구조

Angular 22 / Clarity 18 관리 UI → Python 관리 API / 생성·판단·임베딩 API → LiteLLM 또는 공급자 어댑터 → 공급자 API. PostgreSQL 19를 설정·권한·요청 이력과 사용량의 기준 저장소로 사용한다. Redis는 사용하지 않는다. 초기 단일 인스턴스, 향후 DB 부하를 검증해 다중 인스턴스로 확장한다.

## 데이터와 기능

공급자 유형 → 지역·URL·인증 정보와 그룹을 가진 공급자 연결 → 모델 등록. 공급자 그룹은 범용, 판단 전용, 임베딩 전용으로 구분한다. 범용 공급자는 서로 다른 용도의 모델을 등록할 수 있으며 신규 모델은 생성형·판단형·임베딩 중 실제 용도 하나를 선택한다. 전용 공급자는 해당 용도의 모델만 허용한다. TypeSafe Jev는 판단 전용이다. 목록에서 모델의 용도를 자동으로 추정하지 않으며 운영자가 확인해 지정한다. 이전 버전에서 여러 작업을 가진 모델은 호환성을 위해 유지하지만 신규 등록에는 허용하지 않는다. 임베딩은 차원, 입력 제한, 가격과 배치 지원을 기록한다. 임베딩 전달과 벡터 저장·검색은 별개이며 후자는 범위 밖이다.

목표 API: `GET /v1/models`, `POST /v1/chat/completions`, `POST /v1/decisions`, `POST /v1/embeddings`. 판단 API는 공급자와 LiteLLM의 실제 계약 검증 후 확정한다. OpenAI 호환도 공급자별 파라미터, 스트리밍, 사용량의 차이를 검증한다.

클라이언트 API 키는 해시만 저장하고 발급 시 한 번만 표시한다. 공급자 키는 암호화해 저장하며 암호화 키는 DB와 분리한다. 관리자·클라이언트 권한을 분리하고 본문은 기본적으로 저장하지 않는다. 사용자 정의 URL은 SSRF 방어와 접근 정책이 필요하다. 이용량 미확인과 0을 구분하고 비용은 추정치와 가격 기준을 표시한다. 판단 확률은 업무 데이터로 검증한다.

2026-11-14 기준 PostgreSQL 19는 RC 2이며 GA는 2026-11-19 예정이므로 운영 전 정식 버전과 도구 호환성을 재검증한다([공식 발표](https://www.postgresql.org/about/news/postgresql-187-1712-1616-1520-1425-and-19-rc-2-released-3442/)). 새 ON CONFLICT 기능, REPACK, WAIT 등은 필요와 테스트 결과에 따라 선택한다. 전역 카운터의 DB 경합과 외부 호출의 멱등성을 별도로 설계한다. 외부 API 호출이 정확히 한 번 실행됨을 DB 제약만으로 보장하지 않는다.

## 구현 단계와 상태

0. 기술 검증: PostgreSQL 19 RC, Angular/Clarity 빌드, LiteLLM 계약의 모의 테스트. **진행 중**; 실제 공급자와의 호환성은 검증하지 않았다.
1. 기반: 프로젝트 구성, PostgreSQL 마이그레이션, 상태 점검, CI와 관리 화면 골격 구현.
2. 생성·임베딩: LiteLLM 어댑터, EXAONE 포함 생성 API, 임베딩 API와 모의 공급자 테스트. Cerebras·SambaNova·NVIDIA·Novita·Moonshot·MiniMax·Z.AI·Zhipu·Synthetic·Chutes·Perplexity는 LiteLLM의 생성 요청 주소와 모델 ID를 모의 HTTP 전송으로 검사했다. **진행 중**; 실제 공급자별 호환성은 미검증.
3. 판단: TypeSafe Jev와 OpenAI 판단 모델의 텍스트·이미지 입력 및 TypeSafe Box 판단 API 구현. LiteLLM의 실제 변환과 모의 HTTP로 predicate·choice·score·refusal·Box 응답 및 사용량 기록을 검증한다. TypeSafe 이미지와 Box는 공급자의 실험적 기능이며 명시적 동의가 필요하다. **진행 중**; 실제 공급자 검증은 사용자의 요청에 따라 미실시.
4. 보안·관리: 부트스트랩 인증, 관리자 계정·세션 및 로그인 제한, 오프라인 관리자 복구, 암호화된 공급자 키, API 키 발급·폐기 및 모델 권한 구현. 성공한 설정 변경, 로그인 실패 및 인증된 관리자 요청 실패를 감사한다. **진행 중**; 운영 환경 보안 검증 필요.
5. UI: 로그인, 개요, 공급자·모델·키 관리, 사용량 및 감사 이력을 메뉴별로 제공한다. 격리된 Docker와 모의 공급자에서 키 없는 EXAONE 등록, 키 추가, 생성형·임베딩·판단형 모델 등록 및 호출, 사용량·감사 표시와 날짜·시간 선택을 확인했다. 모의 모델 목록 조회 후 임베딩 모델 선택·등록·수정, 클라이언트 키 발급·만료 시각 수정과 해당 키의 임베딩 호출도 확인했다. 임베딩 전용과 판단 전용 공급자의 모델 용도 제한도 확인했다. **진행 중**; 나머지 등록 흐름과 모바일·스크린 리더 접근성 검증 필요.
6. 운영: 사용량·추정 비용, PostgreSQL 분당 제한, 백업·새 DB 복구, 암호화 키 회전을 구현했다. 과거 예산 원장은 보존하고 기존 예산 키는 차단한다. 격리 PostgreSQL과 모의 공급자로 동시 요청, DB 중지·복구 및 공급자 응답 정체·타임아웃을 검증한다. **진행 중**; 운영 배포 검증 필요.
7. 확장: PostgreSQL을 공유하는 인스턴스의 요청 제한을 구현했다. SSO, 예산·정산, 모델 라우팅과 자동 재시도를 제거했다. 장시간·규모별 테스트는 미완료.

현재 구현은 로컬 개발용이며 초기 부트스트랩 토큰과 생성된 관리자 계정의 세션을 사용한다. 외부 배포 전 계정·세션, TLS, 감사, 요청 제한 및 공급자별 호환성 검증이 필요하다.
