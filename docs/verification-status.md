# 설계 단계별 구현·검증 상태

2026-11-14 기준. 이 문서는 구현 여부와 실제 운영 검증을 구분한다. 공급자 실호출은 사용자 요청 범위 밖이며, 모의 결과로 실제 모델·계정의 호환성을 증명하지 않는다.

| 설계 요구사항 | 현재 근거 | 남은 확인 |

백엔드 고정 의존성 `pip-audit`, 프런트엔드 `npm audit`, 컨테이너 `pip check`와 프런트엔드 CSP 검사는 2026-11-14에 통과했다. 의존성 취약점 결과는 조회 시점에 한정된다. 주요 반복 검증 명령과 부하 시험 조건은 [운영 문서](operations.md)에 있다. CI 워크플로가 저장소에 정의되어 있지만, 로컬 시험 통과가 원격 CI 실행을 의미하지는 않는다. 공개 배포나 공급자 연결을 자동으로 실행하지 않는다.

LiteLLM 프록시 정적 화면과 Python 바이트코드 사전 생성을 제외한 백엔드 이미지에서 네트워크를 끄고 백엔드 테스트 557건을 통과했으며, 별도 PostgreSQL과 모의 공급자를 사용하는 두 인스턴스 시험도 통과했다. 로컬 Docker 이미지 크기는 약 792MB에서 614MB로 줄었다. Docker 실행과 앱 import를 세 번 측정했을 때 원래 이미지는 3.26~4.69초, 축소 이미지는 5.47~5.96초였다. 크기와 시작 시간은 아키텍처와 환경에 따라 달라진다.

추가로 A2A와 MCP 서버 코드를 축소한 이미지에서 외부 네트워크를 차단하고 백엔드 테스트 603건을 통과했으며 32건은 건너뛰었다. LiteLLM 일반 호출이 내부적으로 참조하는 MCP 설정 모듈 `stdio_gate.py`는 유지한다. CI는 프로덕션 이미지에 테스트 도구만 추가한 별도 이미지에서 같은 네트워크 차단 테스트를 반복한다. 이 시험은 모든 공급자의 실제 서비스 호환성을 입증하지 않는다.

LiteLLM 자체 프록시의 관리 API와 Swagger·정적 문서 파일을 추가로 제외한 실험 이미지도 같은 네트워크 차단 테스트에서 603건을 통과하고 32건을 건너뛰었다. Magpie 관리 API는 별도 구현으로 유지한다.

같은 축소 이미지와 격리된 PostgreSQL 19 RC2에서 마이그레이션 및 데이터베이스 통합 검사를 통과했다. 별도의 두 백엔드 시험에서는 모의 임베딩 64건, 생성·판단 각 24건의 동시 요청과 5초간 임베딩 245건을 처리했으며, 사용량·예산 및 공유 요청 제한을 확인했다. 모든 공급자 요청은 모의 처리했으며 테스트 데이터베이스와 컨테이너는 종료 후 삭제했다.

최신 서랍 UI와 격리된 PostgreSQL에서 임베딩 전용 및 Jev 판단 전용 공급자를 등록하고 모의 모델 목록에서 모델을 선택해 등록했다. 각각 허용된 용도만 선택되는 것, 공급자 키 교체 후 이전 목록이 사라지는 것, 두 모델의 모의 관리자 테스트와 사용량·감사 화면을 확인했다. 테스트용 키와 데이터베이스는 시험 후 삭제했다.
