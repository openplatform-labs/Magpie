# 설계 단계별 구현·검증 상태

2026-11-14 기준. 이 문서는 구현 여부와 실제 운영 검증을 구분한다. 공급자 실호출은 사용자 요청 범위 밖이며, 모의 결과로 실제 모델·계정의 호환성을 증명하지 않는다.

| 설계 요구사항 | 현재 근거 | 남은 확인 |
| --- | --- | --- |
| PostgreSQL 19, Redis 미사용 | Compose의 PostgreSQL 19 RC2, Alembic 마이그레이션, `tests/postgres_smoke.py`; 격리된 PostgreSQL 18.7 백업을 19 RC2에 복구하고 테스트 데이터 검증 | PostgreSQL 19 정식 버전 출시 후 이미지와 업그레이드 경로 재검증 |
| Angular 22·Clarity 18 관리 화면 | 컨테이너 빌드와 세션·키 시험, Docker 미리보기에서 로그인·메뉴 전환·모델 및 키 양식 확인 | 개편된 화면의 모바일·스크린 리더 및 전체 등록 흐름 검증 |
| 생성·임베딩·판단 API와 EXAONE·TypeSafe | `/v1` 엔드포인트와 `tests/test_api.py`, `tests/test_native_provider_contracts.py`의 모의 전송 | 실제 공급자·모델별 기능과 장애 응답은 미검증 |
| MCP·A2A 제외, 함수 호출 전달 | 생성 입력 검증 및 공급자 관리 도구 거부 시험 | 새 공급자 어댑터나 API 기능 추가 시 같은 경계 재검증 |
| 공급자 키와 클라이언트 권한 | 키 암호화, 클라이언트 키 해시·일회 표시, PostgreSQL 키 폐기·비활성화 경합 시험 | 실제 배포의 키 관리, 네트워크 egress 및 접근 통제 검토 |
| 판단·임베딩 등록 관리 | 모델 작업 유형과 기능 관리, 차원·배치 입력 검증 시험 | 필요에 따라 운영자가 각 모델의 실제 제공 기능과 판단 품질 확인 |
| 사용량·감사·예산 | 요청별 상태와 감사 기록, 가격·예약·정산 시험, 모의 동시성 시험 | 추정 비용과 실제 공급자 청구액 대사; 운영 보존 정책 결정 |
| 백업·복구 및 고가용성 | 격리된 백업 복구, 장애·정체 및 두 인스턴스 모의 부하 시험; 동시 작업자 4명으로 300초 동안 임베딩 14,117건의 사용량·예산 정합성 확인 | 실제 환경의 장애 복구 훈련, 더 긴 부하 및 배포 설정 검증 |
| OIDC SSO | 로컬 서명 토큰 검증 및 세션 폐기, 두 백엔드에 분산된 모의 콜백의 단일 소비 시험 | 실제 IdP 상호 운용성 및 배포 설정 검증 |

백엔드 고정 의존성 `pip-audit`, 프런트엔드 `npm audit`, 컨테이너 `pip check`와 프런트엔드 CSP 검사는 2026-11-14에 통과했다. 의존성 취약점 결과는 조회 시점에 한정된다. 주요 반복 검증 명령과 부하 시험 조건은 [운영 문서](operations.md)에 있다. CI 워크플로가 저장소에 정의되어 있지만, 로컬 시험 통과가 원격 CI 실행을 의미하지는 않는다. 공개 배포나 공급자 연결을 자동으로 실행하지 않는다.
